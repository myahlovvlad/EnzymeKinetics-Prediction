# Жизненный цикл разработки и научной проверки

## Требования и решения

[Спецификация](specs/PHYSICAL_PIPELINE.md) фиксирует границы релиза и критерии;
[матрица R1–R7](IMPLEMENTATION_STATUS.md) связывает требования с результатами.
[ADR-0001](adr/0001-physical-research-pipeline.md) задаёт владение модулями,
контракты физики и смысл многоблочной проекции. Изменение этих контрактов
требует изменения схемы, тестов и документации, а не скрытой смены метода.

## Реализация и наблюдаемость

- Одна uv-конфигурация и lockfile. Physics/ESM — extras; P2Rank/APBS — внешние
  программы с явной проверкой доступности, subprocess timeout и логами.
- Артефакт физики содержит backend, inputs, settings, values, units,
  cache identity и limitations. JSON записывается атомарно и запрещает NaN.
- Физические таблицы проверяют префиксы, уникальность join keys, числовые
  значения, единицы и checksum. Данные без известного условия не соединяются
  с произвольным условием другого расчёта.
- Каталоги run не перезаписываются. Manifest сохраняет успешные и ошибочные
  стадии. Исходные данные/веса остаются локальными, компактные отчёты — в docs.
- Обучение фиксирует source row, split, версии, seed, хеши кода на старте,
  входов и структур. Scaler/imputer/EC vocabulary обучаются только на train.
  Гиперпараметры и checkpoint выбираются по validation.
- Точные sequence, EC или предоставленные cluster assignments служат ключами
  группировки; `grouped-three-way` разносит все три части. Проверка по
  sequence-cluster column гарантирует отсутствие общего cluster ID, но сама
  по себе не доказывает корректность сторонней кластеризации.

## Проверки перед выпуском

```sh
uv sync --locked --extra physics --extra embeddings
uv run --no-sync ruff check enzyme-kinetics
uv run --no-sync ruff format --check enzyme-kinetics
uv run --no-sync pytest -q
uv pip check
uv build
```

Tests проверяют утечки target/product, инвариантность геометрии, обучение,
сериализацию всех семейств моделей, EC fallback, нормировку MB-PLS,
response-orthogonal deflation OPLS, аналитические единицы поля и TST,
баланс кинетического цикла, обратимую реакцию, Haldane, OpenDX axis order,
целостность таблиц и отказ конфигурации. Native tblite/OpenMM-тесты используют
малые численные системы и пропускаются при отсутствии physics extra.
Отдельный regression test проверяет DCD в пути с кириллицей.

CI содержит core/physics matrix на Linux/Python 3.13. Большие датасеты,
внешние загрузки моделей, P2Rank, APBS и реальные исследовательские прогоны
не являются входами unit-CI. Зелёный CI подтверждает программные контракты,
а не корректность механизма реакции. Локальные реальные расчёты имеют
отдельные [evidence](benchmarks/v2/physical-pilot/manifest.json).
Удалённый CI в этой сессии не запускался.

## Экспериментальная и релизная приёмка

Программная приёмка: тесты/линтер/сборка, фактический backend smoke run,
совпадение reload-предсказаний и явное происхождение артефактов.
Научная приёмка: подготовленная система, assay provenance, сходимость,
независимое измерение и оценка неопределённости. Они принимаются отдельно.

`docs/VALIDATION.json` фиксирует выполненные локальные проверки.
`docs/benchmarks/v2` хранит portable evidence и хеши локальных моделей.
Необходимые данные описаны в DATA_LAYOUT.md; право распространения сторонних
данных/моделей необходимо проверять по их исходным лицензиям. Лицензия автора
репозитория не назначается автоматически.

## Изменения, эксплуатация и откат

Работайте через небольшие проверяемые изменения и PR; сравнивайте результаты
с сохранённым v1. Не выбирайте новую модель по уже просмотренному test.
При сбое сохраняйте manifest/logs, исправляйте причину, запускайте новый
каталог; не меняйте неудачный результат на успешный вручную.
Для отката inference используйте прежний каталог модели вместе с его
preprocessing и embedding inputs. Совместимость v1 проверена отдельно.

Полные протоколы production MD, ES-parameterization, QM/MM и свободной энергии
сначала проходят исследовательский review; их нельзя объявить валидированными
на основании короткой демонстрации. Следующие критерии сформулированы в
IMPLEMENTATION_STATUS.md. CHANGELOG.md фиксирует публичные изменения интерфейса.
