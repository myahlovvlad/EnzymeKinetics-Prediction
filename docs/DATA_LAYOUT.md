# Локальные данные и роли файлов

| Каталог | Назначение | Использование |
| --- | --- | --- |
| `data/Baseline/` | Экспериментальные trainval/test CSV kcat/Km/Ki и срезы | Источник targets для обучения |
| `data/CatPred-DB/data/catpred_progres_embeds_dict.pt` | 13 376 записей, 128-мерные tensor-векторы | Используется, соответствие по UniProt из имени |
| `data/alphafold_pdb/` | 5 570 локальных PDB | Радиальные CA-признаки, SHA-256 в provenance |
| `data/processed/p2rank_out/` | Ранее вычисленные результаты карманов | Сохранены; в текущий benchmark не включены |
| `data/processed/struct_features_advanced.csv` | Заголовок без строк на момент анализа | Не используется как фиктивный физический блок |
| `data/pretrained/reproduce_checkpoints/` | Исходные checkpoint и структурные записи провайдера | Сравнительные/исследовательские материалы; не выдаются за наши обученные веса |
| `data/external/UniKP/`, `data/external/DLKcat/` | Подготовленные признаки и данные внешних подходов | Для отдельной проверки соответствия строк и воспроизведения методов |
| `data/results/` | Исходные результаты провайдера | Справочный материал, отдельно от наших outputs |
| `data/manifests/` | Списки загрузок и отсутствующих структур | Утилиты подготовки данных |
| `outputs/training/{kcat-v1,km-v1}/` | Наши веса, split, метрики и preprocessing | Рабочие модели и inference |

В `pretrained` найден, в частности, файл структурных записей
`km_mean_wt_singleSeqs_wpdbs_pdbrecords.json` размером около 1,96 ГБ.
Он может стать отдельным источником геометрии после проверки схемы,
сопоставления последовательностей и provenance. Сейчас loader использует
локальные PDB и явно сообщает отсутствие примерно половины структур.

Внешние `.pkl`, `.npy` и `.pt` не подключаются автоматически только по имени:
нужно установить соответствие экспериментальным строкам, размерности,
обучающий split, единицы и происхождение представления. Иначе сравнение
превратится в утечку target или смешение разных экспериментов.

Перед распространением локальных исходных данных/весов нужно установить
их точную версию и условия лицензирования. Git содержит код, небольшие
основания исследования и сводные результаты; многогигабайтные материалы
остаются локальными. Исходный архив удалён только после полного сравнения
всех членов с сохранёнными файлами; см. [аудит](ARCHIVE_AUDIT.json).


## Физические признаки 0.2

`data/physical/pockets.csv` содержит 3 841 нормализованный UniProt; sidecar
хранит единицы, checksum и исходные файлы. `quantum.csv` — ограниченный
GFN2-xTB batch: четыре результата, 28 записанных отказов. Весь lookup замораживается
в preprocessing каждого run. Эти CSV исключены из Git как производные локальные
данные; инструкции повторной генерации находятся в PHYSICS.md.

`outputs/backend_checks/p00947-integrated-v4-apbs/` — успешный физический пилот с APBS:
manifest, QM, PQR, pocket, MD DCD/System/checkpoint, trace. Неудачные v2 и
предварительные backend runs сохранены для диагностики; они не считаются
успешными evidence. `outputs/training/*-v2/` — новые модели и новые split.
Компактные отчёты и хеши локальных артефактов находятся в docs/benchmarks/v2/.


## Исследовательская серия 0.3

`data/research/p00947/` — структуры RCSB и required-inputs.json с источниками/SHA-256.
`outputs/experiments/active-site-v3/` — регистрация, события, нормализованный
WT-димер, PQR/APBS, три MD-реплики, потенциальные сканы и capped QM-кластер.
Большие DCD/DX/System остаются вне Git; portable evidence, CSV и дневник —
`docs/experiments/active-site-v3/`. Удачные и отклонённые попытки различаются
по статусам и не превращаются друг в друга без записи корректировки.
