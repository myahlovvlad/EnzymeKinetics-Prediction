# Требования и план реализации физического исследовательского пайплайна

Дата: 1 ноября 2026. Основание: приложенная автором идея шести блоков и запрос
реализовать её с проверяемым SDLC. Рабочая кодовая база и единый uv сохраняются.

## Исходный разрыв

| Требование идеи | Состояние до этого этапа |
| --- | --- |
| P2Rank → активный карман → признаки | Сырые результаты и отдельные скрипты; таблица пуста; не используется при обучении |
| pH-зависимые заряды и электростатика | Нет рабочего блока PDB2PQR/APBS |
| Записанные физические MD-траектории | Только иллюстративные анимации |
| GFN2-xTB, орбитали, диполь, Fukui | Нет рабочего xTB-бэкенда; RDKit/PySCF-скрипт только создаёт молекулы |
| Туннелирование и связь с константами | Произвольные коэффициенты в демонстрациях |
| Семантические блоки, MB-PLS/OPLS, локальные EC-модели | Есть concat → Ridge/PLS/MLP; многоблочные модели отсутствуют |
| ESM-2 | Используются имеющиеся 128-мерные Progres-векторы; это не ESM-2 |
| Независимая проверка | Один seed, exact-sequence split; строгой EC/cluster-проверки нет |

До этого этапа проект — исполняемый эмпирический baseline, а не реализация
квантово-биофизического механизма. Процент готовности без весов требований
не имеет объективного смысла.

## Цель инженерного релиза

Исполняемый, тестируемый исследовательский конвейер с реальными backend:
карман → QM/PQR/MD → именованные блоки признаков → хемометрика → отчёт.
Каждый расчёт сохраняет входы, конфигурацию, версии, единицы, статус и ограничения.
Отсутствующий backend или физическая величина не превращается в нулевой признак.

Релиз ПО не равен доказательству механизма реакции. Без полного assay,
подготовленного ES-комплекса и обоснованного свободноэнергетического протокола
нельзя объявить полученную константу экспериментально валидированным kcat.
HOMO–LUMO gap, разность энергий продукта/субстрата и docking score не являются ΔG‡.

## Этапы и критерии

1. Контракты артефактов и условий; единицы и происхождение. Проверки: неверные
   параметры отвергаются, кэш привязан к входам и параметрам.
2. Реальные структурные карманы и нормализация ID. Проверки: flat/nested P2Rank,
   версии имён, отсутствующий PDB, согласованность остатков.
3. GFN2-xTB через tblite; воспроизводимая геометрия, энергии/орбитали/заряды/диполь,
   вертикальные Fukui. Электронная диссоциация отдельно от термохимической BDE.
4. PDB2PQR с pH, APBS-адаптер и OpenDX. Явно выбранная приближённая
   screened-Coulomb модель допустима только с соответствующей маркировкой.
5. OpenMM: подготовленная система либо стандартный белок, реальные траектории,
   диагностика RMSD/Rg/расстояний/DCCM. Параметры лиганда не придумываются.
6. TST, высокотемпературные приближения туннелирования и микрокинетическая
   сеть. Проверки размерностей, пределов, балансов и идентифицируемости.
7. Общая сборка блоков и подключение к обучению; MB-PLS/OPLS/EC fallback;
   EC/sequence-cluster split; безопасная загрузка и воспроизводимый inference.
8. Интеграционные расчёты на локальном пилоте и обучение на реальных данных;
   CI, документация и матрица подтверждённой готовности.

## Научные границы и приёмка

Короткий MD-прогон — проверка backend, а не достаточное семплирование 10–50 ns.
QM single point на подготовленном конформере — характеристика данной геометрии,
а не поиск TS. Полученный из заданной ΔG‡ k_chem — условный TST-результат;
kcat/Km следуют из явно заданной кинетической схемы.

Проверки должны различать: модуль реализован; backend установлен;
реальный расчёт выполнен; результат сходим и научно проверен.
Последние два статуса не выводятся из первых автоматически.
